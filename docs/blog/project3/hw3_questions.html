1. Likelihood for the Multi-nomial Logit (MNL) Model

Suppose we have \(i=1,\ldots,n\) consumers who each select exactly one product \(j\) from a set of \(J\) products. The outcome variable is the identity of the product chosen \(y_i \in \{1, \ldots, J\}\) or equivalently a vector of \(J-1\) zeros and \(1\) one, where the \(1\) indicates the selected product. For example, if the third product was chosen out of 3 products, then either \(y=3\) or \(y=(0,0,1)\) depending on how we want to represent it. Suppose also that we have a vector of data on each product \(x_j\) (eg, brand, price, etc.).

We model the consumer’s decision as the selection of the product that provides the most utility, and we’ll specify the utility function as a linear function of the product characteristics:

\[ U_{ij} = x_j'\beta + \epsilon_{ij} \]

where \(\epsilon_{ij}\) is an i.i.d. extreme value error term.

The choice of the i.i.d. extreme value error term leads to a closed-form expression for the probability that consumer \(i\) chooses product \(j\):

\[ \mathbb{P}_i(j) = \frac{e^{x_j'\beta}}{\sum_{k=1}^Je^{x_k'\beta}} \]

For example, if there are 3 products, the probability that consumer \(i\) chooses product 3 is:

\[ \mathbb{P}_i(3) = \frac{e^{x_3'\beta}}{e^{x_1'\beta} + e^{x_2'\beta} + e^{x_3'\beta}} \]

A clever way to write the individual likelihood function for consumer \(i\) is the product of the \(J\) probabilities, each raised to the power of an indicator variable (\(\delta_{ij}\)) that indicates the chosen product:

\[ L_i(\beta) = \prod_{j=1}^J \mathbb{P}_i(j)^{\delta_{ij}} = \mathbb{P}_i(1)^{\delta_{i1}} \times \ldots \times \mathbb{P}_i(J)^{\delta_{iJ}}\]

Notice that if the consumer selected product \(j=3\), then \(\delta_{i3}=1\) while \(\delta_{i1}=\delta_{i2}=0\) and the likelihood is:

\[ L_i(\beta) = \mathbb{P}_i(1)^0 \times \mathbb{P}_i(2)^0 \times \mathbb{P}_i(3)^1 = \mathbb{P}_i(3) = \frac{e^{x_3'\beta}}{\sum_{k=1}^3e^{x_k'\beta}} \]

The joint likelihood (across all consumers) is the product of the \(n\) individual likelihoods:

\[ L_n(\beta) = \prod_{i=1}^n L_i(\beta) = \prod_{i=1}^n \prod_{j=1}^J \mathbb{P}_i(j)^{\delta_{ij}} \]

And the joint log-likelihood function is:

\[ \ell_n(\beta) = \sum_{i=1}^n \sum_{j=1}^J \delta_{ij} \log(\mathbb{P}_i(j)) \]

2. Simulate Conjoint Data

We will simulate data from a conjoint experiment about video content streaming services. We elect to simulate 100 respondents, each completing 10 choice tasks, where they choose from three alternatives per task. For simplicity, there is not a “no choice” option; each simulated respondent must select one of the 3 alternatives.

Each alternative is a hypothetical streaming offer consistent of three attributes: (1) brand is either Netflix, Amazon Prime, or Hulu; (2) ads can either be part of the experience, or it can be ad-free, and (3) price per month ranges from $4 to $32 in increments of $4.

The part-worths (ie, preference weights or beta parameters) for the attribute levels will be 1.0 for Netflix, 0.5 for Amazon Prime (with 0 for Hulu as the reference brand); -0.8 for included adverstisements (0 for ad-free); and -0.1*price so that utility to consumer \(i\) for hypothethical streaming service \(j\) is

\[ u_{ij} = (1 \times Netflix_j) + (0.5 \times Prime_j) + (-0.8*Ads_j) - 0.1\times Price_j + \varepsilon_{ij} \]

where the variables are binary indicators and \(\varepsilon\) is Type 1 Extreme Value (ie, Gumble) distributed.

import numpy as np
import pandas as pd
from itertools import product

np.random.seed(123)

brands = ["N", "P", "H"]  
ads = ["Yes", "No"]
prices = np.arange(8, 33, 4)  

profiles = pd.DataFrame(list(product(brands, ads, prices)), columns=["brand", "ad", "price"])
m = profiles.shape[0]

brand_utils = {"N": 1.0, "P": 0.5, "H": 0.0}
ad_utils = {"Yes": -0.8, "No": 0.0}
price_util = lambda p: -0.1 * p

n_peeps = 100
n_tasks = 10
n_alts = 3

def simulate_respondent(pid):
    all_tasks = []
    for t in range(1, n_tasks + 1):
        sampled = profiles.sample(n=n_alts).copy()
        sampled["resp"] = pid
        sampled["task"] = t

        v = (
            sampled["brand"].map(brand_utils) +
            sampled["ad"].map(ad_utils) +
            sampled["price"].apply(price_util)
        ).round(10)
        
        e = -np.log(-np.log(np.random.uniform(size=n_alts)))
        u = v + e

        choice = (u == u.max()).astype(int)

        sampled["choice"] = choice
        all_tasks.append(sampled)
    
    return pd.concat(all_tasks, ignore_index=True)

conjoint_data = pd.concat([simulate_respondent(i) for i in range(1, n_peeps + 1)], ignore_index=True)

4. Estimation via Maximum Likelihood

def mnl_log_likelihood(beta, X, y, n_alts=3):
    beta = np.asarray(beta)
    n_tasks = len(y) // n_alts

    utilities = X @ beta
    utilities = utilities.reshape(n_tasks, n_alts)
    y = y.reshape(n_tasks, n_alts)

    exp_u = np.exp(utilities)
    probs = exp_u / np.sum(exp_u, axis=1, keepdims=True)

    log_probs = np.log(probs)
    chosen_log_probs = (y * log_probs).sum(axis=1)
    return chosen_log_probs.sum()
from scipy.special import gammaln
from scipy.optimize import minimize
import numpy as np

def neg_log_likelihood(beta, X, y, n_alts=3):
    return -mnl_log_likelihood(beta, X, y, n_alts)

beta_init = np.zeros(X.shape[1])

5. Estimation via Bayesian Methods

import numpy as np
n_alts = 3
n_params = X.shape[1]

def mnl_log_likelihood(beta, X, y, n_alts=3):
    beta = np.asarray(beta)
    n_tasks = len(y) // n_alts
    utilities = X @ beta
    utilities = utilities.reshape(n_tasks, n_alts)
    y = y.reshape(n_tasks, n_alts)
    exp_u = np.exp(np.clip(utilities, -700, 700))  
    probs = exp_u / np.sum(exp_u, axis=1, keepdims=True)
    log_probs = np.log(probs)
    return (y * log_probs).sum()

def log_prior(beta):
    logp = -0.5 * (beta[0:3]**2 / 5 + np.log(2*np.pi*5)).sum()
    logp += -0.5 * (beta[3]**2 / 1 + np.log(2*np.pi*1))
    return logp
def log_posterior(beta, X, y):
    return mnl_log_likelihood(beta, X, y, n_alts) + log_prior(beta)

n_draws = 11000
burn_in = 1000
beta_samples = np.zeros((n_draws, n_params))

current_beta = np.zeros(n_params)
current_logpost = log_posterior(current_beta, X, y)

proposal_sd = np.array([0.05, 0.05, 0.05, 0.005])

for t in range(n_draws):
    proposal = current_beta + np.random.normal(0, proposal_sd)
    proposal_logpost = log_posterior(proposal, X, y)
    
    log_accept_ratio = proposal_logpost - current_logpost
    if np.log(np.random.rand()) < log_accept_ratio:
        current_beta = proposal
        current_logpost = proposal_logpost
    
    beta_samples[t, :] = current_beta

posterior_samples = beta_samples[burn_in:]

param_names = ["beta_netflix", "beta_prime", "beta_ads", "beta_price"]
posterior_summary = pd.DataFrame({
    "Mean": posterior_samples.mean(axis=0),
    "Std. Dev": posterior_samples.std(axis=0),
    "2.5%": np.percentile(posterior_samples, 2.5, axis=0),
    "97.5%": np.percentile(posterior_samples, 97.5, axis=0)
}, index=param_names).round(4)

Comparison of MLE and Bayesian Estimates

The table above shows that the Maximum Likelihood Estimates (MLE) and Bayesian posterior means are very close, but not identical.

This is expected: - The MLE estimates are purely driven by the data, finding the parameter values that maximize the likelihood. - The Bayesian estimates incorporate prior beliefs, which exert a small “pull” on the posterior means — especially when data is moderate in size.

Because we used weakly informative priors, the differences between MLE and posterior means are minimal, and their confidence/credible intervals overlap almost completely.

These small differences validate our MCMC sampler and show that both estimation methods are consistent and reliable.

Extending to a Hierarchical (Multilevel) Model

To move from the basic MNL model to a hierarchical MNL model , we would need to make one key change:

Instead of assuming a single, fixed set of betas shared by all respondents…

We allow each respondent i to have their own parameter vector beta_i :

\[ \beta_i \sim \mathcal{N}(\mu, \Sigma) \] Where: - \(\mu\) is the average (population-level) preference across respondents, - \(\Sigma\) is the covariance matrix that captures heterogeneity across people

This structure reflects the reality that different consumers have different tastes — some value price more, others care more about brand or ads.

Changes to Data Simulation

To simulate hierarchical data, we would: - Draw a personalized beta_i for each respondent from a multivariate normal prior - Use beta_i to generate choices for that respondent across all tasks

This adds individual-level variation into the data-generating process.

Changes to Estimation

To estimate a hierarchical MNL model, we would: - Treat the beta_i’s as latent variables - Place a prior on \(\mu\) and \(\Sigma\) - Use Bayesian methods like Gibbs sampling or Hamiltonian Monte Carlo to jointly estimate: - Each person’s beta_i - The population-level parameters \(\mu\), \(\Sigma\)

This is more computationally intensive, but it provides: - Individual-level part-worths - More accurate market share predictions - The ability to segment respondents by preference patterns

Why Use a Hierarchical Model?

In real-world conjoint analysis, hierarchical models are the standard because: - They reflect real consumer heterogeneity - They improve prediction and personalization - They allow more flexible and realistic simulations of market behavior
